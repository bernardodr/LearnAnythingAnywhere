Entities & API Design

Steps 2 and 3 of the delivery framework, about 7 minutes in total.

Core entities (~2 min)

  • Find them from the actors and the nouns in your functional requirements.
  • Write a bullet list of clear names. Fields come later, during the high-level design.

Choosing a protocol

ProtocolUse when
RESTUse it by default.
GraphQLMany different clients need different data shapes.
RPC (gRPC)Performance-critical, internal service-to-service calls.
WebSockets / SSEReal-time updates. Add them only after the core API.

REST conventions

VerbMeaningExample
POSTCreatePOST /urls
GETReadGET /tweets/{id}
PUT / PATCHReplace / partially updatePATCH /urls/{code}
DELETERemoveDELETE /urls/{code}
  • Plural nouns in paths, no verbs: /tweets, not /createTweet.
  • One endpoint per functional requirement.
  • Get the current user from the auth token in the header, never from the body.
  • Optional features in the requirements become optional request fields.
