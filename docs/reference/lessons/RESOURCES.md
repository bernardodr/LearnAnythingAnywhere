# System Design Interview Resources

## Knowledge

- [Hello Interview: System Design in a Hurry, Delivery Framework](https://www.hellointerview.com/learn/system-design/in-a-hurry/delivery)
  Written by ex-Meta/Amazon interviewers. The time-boxed 6-step framework this course uses. Use for: interview structure, pacing, what to say in each phase.
- [Hello Interview: What is Expected at Each Level](https://hellointerview.com/blog/the-system-design-interview-what-is-expected-at-each-level)
  Breadth / depth / proactiveness expectations by level. Use for: calibrating what a mid-level answer needs (and doesn't need).
- [MDN: HTTP response status codes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status)
  Authoritative definitions of status codes. Use for: 301 vs 302, 4xx semantics.
- [Hello Interview: Bitly problem breakdown](https://www.hellointerview.com/learn/system-design/answer-keys/bitly)
  Worked answer for the classic first problem. Use for: first full mock and model answer.
- [Video: "Beginner System Design Interview: Design Bitly w/ a Ex-Meta Staff Engineer" (Hello Interview)](https://www.youtube.com/watch?v=iUU4O1sWtJA)
  Walkthrough pitched at junior/mid candidates. Use for: seeing the framework run live.
- [Book / course: Alex Xu, *System Design Interview: An Insider's Guide* (ByteByteGo)](https://bytebytego.com/courses/system-design-interview/a-framework-for-system-design-interviews)
  The standard interview-prep book. Its 4-step framework (scope → high-level → deep dive → wrap up) maps onto Hello Interview's. Use for: classic problem chapters, diagrams.
- [GitHub: donnemartin/system-design-primer](https://github.com/donnemartin/system-design-primer)
  Free, very widely used. Covers fundamentals (scaling, caching, CAP, DBs) with Anki decks. Use for: building-block fundamentals. Some content is dated, so verify against current docs.

## Wisdom (Communities)

- [r/ExperiencedDevs](https://www.reddit.com/r/ExperiencedDevs/) and [r/cscareerquestions](https://www.reddit.com/r/cscareerquestions/)
  Use for: interview experience reports and calibration. Noisy, so read critically.
- Peer mock interviews (e.g. with friends or colleagues, or a free peer-mock platform) — to research
  Use for: real-time practice under pressure. This is the highest-value wisdom source for interviews.
