The Delivery Framework

The route through any 45–60 minute "Design X" round.

Reqs Ent. API High-Level Design Deep Dives

Minutes: 5 · 2 · 5 · 10–15 · 10

StepTimeDoDon't
1. Requirements~5 ~3 functional ("Users should be able to…"). 3–5 non-functional, quantified (latency, scale, availability/consistency, durability, security). List every feature. Do math that won't change the design.
2. Core Entities~2 Bullet list of nouns and actors. Use clear names. Write the full schema yet.
3. API~5 One endpoint per functional requirement. Default to REST with plural nouns. Get the user from the auth token. Put userId in the request body. Reach for WebSockets before the core API exists.
4. Data Flow~5 Optional. Ordered list of steps for pipeline-style systems. Use it for simple CRUD systems.
5. High-Level Design10–15 Go endpoint by endpoint. Show how data moves from request to response. Include only the schema fields that matter. Add caches, queues or shards early. Note them and move on.
6. Deep Dives~10 Meet the non-functional requirements. Fix bottlenecks and edge cases. Respond to probes. Talk over the interviewer.

What "mid-level" means here

  • Breadth over depth. Know what every component you mention does and why it's there.
  • Lead steps 1–5 yourself. In step 6, expect the interviewer to steer.
