# Learn Anything Anywhere (LAA): prototype brief

You are building a working prototype of **Learn Anything Anywhere (LAA)**. It's a cross-platform app that turns anything a person wants to learn into their own textbook, written around *why* they want to learn it. Its teaching method comes from Matt Pocock's `/teach` skill. The backend has an **LLM gateway** that lets the owner switch between providers (OpenAI, Google Gemini, Anthropic Claude and others) without code changes.

Read this whole brief before writing any code.

## 1. What LAA is

- A user signs up and lands on their **library** (a bookshelf of textbooks).
- The **+** button starts a new textbook. The app interviews them about *why* they want to learn the topic (the **mission**), then generates short, interactive **lessons** tied to that mission.
- Each textbook keeps its state on the server as Markdown files, exactly as `/teach` keeps a workspace on disk. Learners can leave and come back on any device.
- `/teach` asks long-form questions that you answer back in the terminal. LAA answers them **in the app** instead: a **tutor** model grades the answer against a hidden rubric and replies with hints or questions, **never the answer**.
- Parents and owners get **safety controls**: child-safe mode, an age slider and content filters.
- The **owner console** (web) lets the service owner switch the LLM provider per task.

### Source method: `/teach` (MIT licensed)

Clone `https://github.com/mattpocock/skills` into `docs/reference/skills` (git-ignored) and read `skills/productivity/teach/`:
`SKILL.md`, `MISSION-FORMAT.md`, `LEARNING-RECORD-FORMAT.md`, `GLOSSARY-FORMAT.md` and `RESOURCES-FORMAT.md`.

- Port its **philosophy and file formats faithfully**: mission first, trusted resources, zone of proximal development, knowledge then skills, retrieval practice, spacing, interleaving, and learning records only on evidence.
- Add `THIRD_PARTY_NOTICES.md` with the MIT license text and copyright notice from that repo.
- Two example lessons generated by `/teach` are in `docs/reference/lessons/`. Use them as the model for lesson **structure and tone**. LAA's version renders natively from JSON (section 7), not from HTML.

## 5. LLM gateway (core requirement)

**Goal:** every model call goes through one gateway. **The owner** chooses which provider handles each task, from the owner console, with **no redeploy**. Learners never choose a model.

### 5.1 Interfaces

```java
public interface LlmGateway {
  <T> T structured(Task task, PromptContext ctx, Class<T> type, GenerationProfile profile);
  Flux<String> stream(Task task, PromptContext ctx, GenerationProfile profile);   // or a callback-based stream if you avoid Reactor
}

enum Task { MISSION_INTERVIEW, RESEARCH, LESSON_PLAN, LESSON_WRITE, TUTOR, GRADE, RECORD_UPDATE, SAFETY_CHECK }
enum Provider { OPENAI, GOOGLE, ANTHROPIC, OLLAMA, FAKE }

record Route(Task task, Provider provider, String model, Map<String,Object> params,
             String promptVersion, List<Provider> fallbacks) {}
```

### 5.2 Behaviour

- **One Spring AI `ChatClient` per configured provider**, built at startup only for providers whose key or URL is present: `OPENAI_API_KEY`, `GEMINI_API_KEY` (Google GenAI starter), `ANTHROPIC_API_KEY`, `OLLAMA_BASE_URL`. The `FAKE` provider is always available.
- **`ModelRouter`** resolves the `Route` for each call from `model_routes` and `providers`, with a short cache. Updating a route through the API invalidates the cache, so **the next call uses the new provider**.
- **Default provider:** routes with `provider_choice = DEFAULT` follow the provider flagged `is_default`. Changing the default moves all of them at once.
- **Model selection:** each provider lists models with a tier (`LARGE`/`SMALL`). A route picks a tier, or overrides with a specific model ID. **Model IDs are config, not code**: seed them from `application.yml` defaults, and look up current IDs in each provider's docs when you write the seed.
- **Fallbacks:** on timeout, rate limit, 5xx or a provider error, try the route's fallback providers in order. Record the outcome in `model_runs` with status `FALLBACK`.
- **Capability checks:** each model declares `structuredOutput`, `toolCalling`, `streaming` and `maxContext`. Reject (with HTTP 400) a route change that gives a task a model without what it needs (see 5.3).
- **Structured output:** use Spring AI structured output with a JSON schema. Validate the result; on failure retry once with the validation errors appended, then fail with a clear error.
- **Prompts** are provider-neutral, versioned files: `server/src/main/resources/prompts/<task>.v1.md`. The route names the prompt version. The adapters handle provider differences.
- **Metering:** every call writes a `model_runs` row (provider, model, tokens, rough cost, latency, status, safety flags).
- **Keys** never leave the server and are never logged.
- **Fake provider:** deterministic canned outputs per task, used in tests and when no keys are set, so the whole app can be demoed offline.

### 5.3 What each task needs

| Task | Purpose | Needs | Default tier |
|---|---|---|---|
| `MISSION_INTERVIEW` | Ask why; push back on vague goals; finish with a mission draft | streaming, structured output (final draft) | LARGE |
| `RESEARCH` | Find and annotate trusted resources (stretch) | tool calling | LARGE |
| `LESSON_PLAN` | Pick the next lesson from mission + learning records (zone of proximal development) | structured output | LARGE |
| `LESSON_WRITE` | Write lesson JSON (section 7) | structured output | LARGE |
| `TUTOR` | Socratic chat inside a lesson | streaming | SMALL |
| `GRADE` | Score a free response against the rubric | structured output | SMALL |
| `RECORD_UPDATE` | Propose learning records and glossary changes from evidence | structured output | SMALL |
| `SAFETY_CHECK` | Classify topics, generated content and chat | structured output | SMALL |

### 5.4 Owner API (role `OWNER` only)

- `GET /owner/providers`; `PATCH /owner/providers/{id}` (enable or disable, set default)
- `GET /owner/routes`; `PATCH /owner/routes/{task}` (provider choice, tier or model, fallbacks, params, prompt version)
- `GET /owner/runs?task=&provider=&limit=`
- `POST /owner/compare`: same task and input run through two routes, returning both outputs plus automatic checks (schema valid, quiz rules, moderation result, estimated reading age)

### 5.5 Acceptance tests

- Changing the default provider changes the provider in the **next** `model_runs` row for routes set to `DEFAULT`.
- A per-task override wins over the default.
- A failing primary provider (fake, configured to fail) falls back to the next provider, and the run is logged as `FALLBACK`.
- Assigning a model without tool calling to `RESEARCH` is rejected.
- No API key appears in logs or API responses.

## 6. Teaching engine (port of `/teach`)

### 6.1 Context assembly
Every teaching call loads the textbook's workspace files into the prompt: mission, glossary, recent learning records, notes and resources. Then it adds the learner's **generation profile** rules (section 8).

### 6.2 Mission interview
- `MISSION_INTERVIEW` streams questions. Push back on vague goals, as `MISSION-FORMAT.md` says. Stop after about 2–5 turns.
- Finish with a structured draft: why, success looks like, constraints, out of scope.
- The app shows the draft as a mission card. On confirmation, write `MISSION.md` in the exact format.

### 6.3 Resources
- **Never invent URLs or citations.** If no research tool is configured, `RESOURCES.md` lists only resources the learner adds, and lessons carry no external citations. Show a small "no sources yet" note.
- Stretch: if `SEARCH_API_KEY` is set, give `RESEARCH` a web-search tool, then verify each URL resolves before saving it.

### 6.4 Lessons
- `LESSON_PLAN` picks one tightly scoped skill in the learner's zone of proximal development, tied to the mission.
- `LESSON_WRITE` produces lesson JSON (section 7). The server validates it, normalises the quizzes, stores it, and removes rubrics before sending it to the client.
- Lessons are short: one tangible win, knowledge first, then practice with immediate feedback.
- Each lesson opens with a warm-up question from an earlier lesson when one exists, for spaced retrieval.

### 6.5 Tutor and grading
- **Free response:** `GRADE` returns `{verdict: MET|PARTIAL|NOT_YET, coveredPoints[], missingPoints[], coachingMove: CONFIRM|ASK|HINT, message}`.
- **Leak guard:** before replying, check the message doesn't restate rubric text (compare text similarity, plus a `SAFETY_CHECK`-style classifier). If it does, regenerate once, then fall back to the next hint.
- **Hint ladder:** about three hints per question, from gentle to strong. Reveal the answer only if the profile's `reveal_after_attempts` allows it.
- **Tutor chat:** knowledge can be explained freely; practice gets coached with questions, never solved outright.
- **Evidence:** after a `MET` verdict on a non-trivial point, run `RECORD_UPDATE`. It may write a learning record (in `LEARNING-RECORD-FORMAT.md` format) or promote a glossary term the learner used correctly. Covering material alone is not evidence.

## 7. Lesson JSON

```json
{
  "seq": 4,
  "kicker": "Lesson 4 · Bouldering",
  "title": "Bring the wall to your hips",
  "subtitle": "Why your forearms give out on steep problems, and how your legs can take the load instead.",
  "win": "You'll be able to explain why turning a hip in saves your arms…",
  "missionLink": "Climb a V3 with my friends by spring",
  "blocks": [
    { "id": "b1", "type": "quiz", "variant": "warmup", "question": "…", "options": ["…","…","…"], "answer": 1, "explanation": "…" },
    { "id": "b2", "type": "heading", "text": "Where your weight goes" },
    { "id": "b3", "type": "text", "md": "…", "citations": ["r1"] },
    { "id": "b4", "type": "callout", "kind": "watch_out", "text": "…" },
    { "id": "b5", "type": "quiz", "variant": "check", "question": "…", "options": ["…","…","…"], "answer": 2, "explanation": "…" },
    { "id": "b6", "type": "steps", "title": "Try it at the gym", "items": ["…","…"] },
    { "id": "b7", "type": "free_response", "prompt": "…", "hints": ["…","…","…"] },
    { "id": "b8", "type": "primary_source", "resource": "r1", "note": "…" },
    { "id": "b9", "type": "ask_tutor", "examples": ["…","…"] }
  ],
  "referenceSheet": { "title": "Body position", "md": "…" }
}
```

- **Block types:** `heading`, `text` (Markdown), `key_idea`, `callout` (`win`/`note`/`watch_out`), `quiz` (`warmup`/`check`), `steps`, `free_response`, `primary_source`, `ask_tutor`, and optionally `diagram` (Mermaid source, rendered on web only in the prototype).
- **Rubrics** come back from `LESSON_WRITE` keyed by block ID and are stored in `lessons.rubrics`. They are never sent to the client.
- **Quiz rules, enforced in code:** options of similar length (within about 20% of characters and the same word count, plus or minus 1); the server shuffles options and remaps the answer index; no option may be "all of the above" or similar.
- **Citations** must reference IDs in `RESOURCES.md`; drop any that don't.
- Quiz answers may go to the client, so quiz feedback is instant.

## 8. Safety

Safety is enforced in LAA's own layer, so **switching provider never turns it off**.

- **Generation profile** (per learner, set by a parent for child profiles): age, child-safe mode, filter categories (violence and weapons, mature themes, drugs and alcohol, gambling, scary content, plus a free list), links policy, and reveal-after-attempts.
- **Topic gate:** `SAFETY_CHECK` runs on the topic when a textbook is created and returns `ALLOW`, `REFRAME` (with an age-appropriate framing) or `DECLINE` (with a kind message).
- **Prompt rules:** the profile is rendered into explicit rules in every system prompt: reading level for the age, which categories to leave out, and the links policy.
- **Output moderation:** every generated lesson block, tutor reply and grading message passes `SAFETY_CHECK` before it's saved or sent. Learner chat input is checked too. A block that fails is regenerated once, then replaced with a safe placeholder and logged.
- **Links policy:** enforced on the server by stripping or allowlisting links in Markdown, not only by prompt.
- **Child profiles** (age under 13) can only be created under a `PARENT` account. In the prototype, use a parent PIN stub on the settings screen.
- **Red-team smoke test:** `server/src/test/resources/redteam-topics.txt` holds about 15 risky topics. A test asserts the gate returns `DECLINE` or `REFRAME` for a child profile, using the fake provider, plus a manual script that runs the same list against real providers.

## 13. Demo script (definition of done)

1. Sign in as a learner and see the empty shelf.
2. Tap **+** and enter "Bouldering". Complete the preface interview and confirm the mission.
3. Open lesson 1. Answer the quiz, then submit a partial free response and get a tutor's note with a hint, not the answer.
4. Revise the answer to `MET`. A learning record appears under "What you've learned".
5. Sign in as the owner. In the console, switch `LESSON_WRITE` from Anthropic to Google Gemini.
6. Back as the learner, generate lesson 2. The owner's run log shows it came from Gemini.
7. Switch the learner to a child profile aged 9 with child-safe on. Try a topic from the red-team list and see a kind decline or an age-appropriate reframe.
